# 平台字数规范（章节字数目标校准）

> 定位：`字数目标`的**唯一校准依据**。选题（/nww-topic）选定发布平台 → 写入 bible.json `platform` 字段 → 建书/排细纲时按本表设定章节字数目标。
> 原则：**模糊即可，以平台官方创作规范为准**——本表数字是校准参考（采集自平台官方建议与主流实践，平台规则随时可调，以发文时平台后台提示为准），不是硬性精确值。
> 系统硬下限：任何平台的`字数目标`不得低于 **2000 字**（visible_chars_v1 口径）。

## 平台参考表

| 平台 | 章节字数参考 | 说明 |
|---|---|---|
| 番茄 | **2000-2500** | 官方建议区间；完读率优先，短章快节奏；日更字数影响全勤/广告分成，单章以完读率为纲 |
| 起点 | 3000-4500 | 主流单章区间；全勤等激励按**日更总字数**（约 4000/日）计，与单章口径分开 |
| 七猫 | 2000-2500 | 快节奏短章逻辑，同番茄 |
| 飞卢 | 2000-2500 | 快节奏、高频更新 |
| 晋江 | 3000-6000 | 女频节奏，章节弹性大 |
| 知乎（盐言故事） | 按短篇结构 | 短篇/中篇逻辑，不按网文长篇单章口径，以整体篇幅结构为准 |
| 其他/未收录 | 以平台官方规范为准 | 建书时查平台创作者后台/官方活动说明，把查到的口径补进本表（附日期） |

## 使用规则

1. **有区间建议的平台**（番茄/七猫/飞卢/晋江）：细纲`字数目标`写**区间格式**（如 `2000-2500`）。校验器对区间目标按区间本身判达标带（`nww_wordcount.py` 已支持 `2000-2500` / `2000~2500` 等写法）。
2. **单值口径的平台**（起点）：写单值（如 `3500`），系统自动按上下浮动 8% 计达标带。
3. **bible.json 缺 `platform` 字段**（存量书）：沿用本书已定稿的`字数目标`，**不追溯改写**既有细纲；补录 platform 后从下一章起生效。
4. 全书`字数目标`统一，禁止按章节剧情随意调整；确需变更（如平台规则变化、全勤策略调整）属建书级决策，更新 bible/约定后对新章生效并留痕。
