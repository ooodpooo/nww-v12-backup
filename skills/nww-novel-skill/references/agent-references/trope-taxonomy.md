# 剧情结构指纹枚举库（Trope Taxonomy）

> **用途**：`nww_trope_guard.py` 的枚举校验与 CD 冷却配置的唯一权威来源。细纲 `structural_fingerprint` 区块的所有一级标签必须取自本文档枚举，不在枚举内 → BLOCKING。
>
> **设计原则**：通用枚举（主结构）+ `genre_context`（题材皮肤）。枚举描述的是**跨题材同构的叙事骨骼**，不是题材-specific 的表面元素。玄幻的"拍卖行加价打脸"和都市的"商业竞拍截胡"在 `core_trope` 层同为 `AUCTION_BIDDING`，题材差异由 `genre_context` 承载。
>
> **版本**：v1.0（2026-09-07，Step 1 P0 初始版）

---

## 一、指纹字段总览

细纲顶部 YAML frontmatter 的 `structural_fingerprint` 区块包含以下字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `conflict_pattern` | 枚举 | ✅ | 核心冲突模式（22种） |
| `conflict_subtype` | 自由文本 | ❌ | 冲突子类型细粒度描述 |
| `core_trope` | 枚举 | ✅ | 核心桥段（45种） |
| `trope_variant` | 自由文本 | ❌ | 桥段变奏描述（冷却恢复期内必须与上次不同） |
| `golden_finger_mode` | 枚举 | ✅ | 金手指用法（18种） |
| `resolution_cost` | 枚举 | ✅ | 解决代价（12种） |
| `character_dynamic` | 枚举 | ✅ | 角色交互模式（18种） |
| `genre_context` | 自由文本 | ✅ | 题材上下文（如"玄幻-宗门演武"、"都市-商业竞拍"） |
| `core_plot_summary` | 自由文本 | ✅ | 核心情节一句话总结（≤80字，用于SimHash计算） |
| `repeat_intent` | 枚举 | ❌ | 有意重复标记（默认`none`，非none时触发白名单豁免校验） |

## 二、conflict_pattern（核心冲突模式，22种）

> CD 冷却：**15~20章**。冲突模式有限，不可避免会多次出现，但绝不能连续发生。

| 枚举值 | 定义 | 正例 | 反例（不应归此类） |
|--------|------|------|-------------------|
| `PROVOKE_SLAP` | 被挑衅后反击打脸，核心是"先抑后扬"的落差 | 宗门大比被嘲笑→一击破防；酒局被羞辱→亮出身份震慑 | 主动找茬欺负人（那是`POWER_STRUGGLE`） |
| `MORAL_DILEMMA` | 两难抉择，两个选项都有代价，核心是"选哪个都痛" | 救亲人还是救百人；守承诺还是揭真相 | 简单的"打不打"选择（那是`FORCED_CHOICE`） |
| `RESOURCES_SNATCH` | 资源/宝物/机会的争夺，核心是"稀缺性驱动" | 抢灵药、夺秘宝、争名额、截胡拍卖 | 日常资源收集（无冲突则不算） |
| `BETRAYAL_REVENGE` | 被背叛后的复仇，核心是"信任破裂后的反击" | 兄弟反目后清算；下属背叛后反杀 | 单纯的复仇（无背叛前置那是`POWER_STRUGGLE`） |
| `ASYMMETRIC_INFO_DEFENSE` | 信息差攻防，核心是"我知道你不知道的" | 手握内幕反制对手；利用信息差设局 | 单纯的调查（无攻防那是`TRUTH_UNCOVER`） |
| `TRAP_ENTRAPMENT` | 陷阱围猎，核心是"请君入瓮" | 诱敌深入后围杀；设局钓鱼执法 | 被动落入陷阱（那是`SURVIVAL_CRISIS`） |
| `IDENTITY_THREAT` | 身份/秘密面临暴露威胁，核心是"伪装即将被撕开" | 卧底身份差点被识破；隐藏实力被怀疑 | 身份已经暴露（那是`SECRET_EXPOSURE`桥段） |
| `POWER_STRUGGLE` | 权力/地位/话语权的博弈，核心是"谁说了算" | 宗门争位、朝堂党争、家族夺权、商业竞争 | 单纯的打架（无权力诉求那是`ARENA_DUEL`桥段） |
| `SURVIVAL_CRISIS` | 生存危机，核心是"活下去" | 绝境逃亡、重伤求生、被困荒岛、末世挣扎 | 有准备的冒险（那是`TREASURE_HUNT`桥段） |
| `TRUTH_UNCOVER` | 真相/秘密的揭露，核心是"水落石出" | 查明真凶、揭开阴谋、还原往事 | 单纯的调查（无揭露结果那是`UNDERCOVER_PROBE`桥段） |
| `DEAL_NEGOTIATION` | 交易/谈判，核心是"条件博弈" | 利益交换、和谈交涉、赎金谈判 | 强取豪夺（无谈判那是`RESOURCES_SNATCH`） |
| `PUBLIC_HUMILIATION` | 公开场合的羞辱/贬低，核心是"面子被踩" | 当众被退婚、宴席被嘲讽、朝堂被弹劾 | 私下的羞辱（无公开性那是`PROVOKE_SLAP`的前置） |
| `HIDDEN_ENEMY_STRIKE` | 暗敌偷袭，核心是"不知道是谁在打我" | 夜行遇袭、暗中下毒、幕后黑手操作 | 明面上的敌人攻击（那是`POWER_STRUGGLE`） |
| `COMPETITION_ELIMINATION` | 竞赛/考核中的淘汰，核心是"排名/晋级" | 大比淘汰、科举落榜、选秀淘汰 | 单纯的比试（无淘汰机制那是`ARENA_DUEL`桥段） |
| `FORCED_CHOICE` | 被迫做出选择，核心是"外部压力下的抉择" | 被逼选边站、被迫放弃某物、限时抉择 | 主动的策略选择（那是`POWER_STRUGGLE`） |
| `RESCUE_OPERATION` | 营救行动，核心是"救人" | 劫狱救人、战场救友、深入敌营救亲 | 自救（那是`SURVIVAL_CRISIS`） |
| `CONSPIRACY_EXPOSE` | 阴谋被揭露，核心是"幕后布局被撕开" | 揭穿篡位阴谋、曝光贪腐网络、撕开邪教布局 | 单纯的真相揭露（无阴谋结构那是`TRUTH_UNCOVER`） |
| `TERRITORY_DEFENSE` | 领地/地盘/据点的防守，核心是"守住家园" | 守城战、护山阵、保卫宗门、守住店铺 | 进攻敌方领地（那是`POWER_STRUGGLE`） |
| `REPUTATION_CRISIS` | 名誉/口碑危机，核心是"名声要毁" | 被造谣抹黑、作品被剽窃、商誉被攻击 | 已经名誉扫地（那是`PUBLIC_HUMILIATION`的后果） |
| `FORBIDDEN_KNOWLEDGE` | 禁忌知识/禁术/秘密的触碰，核心是"不该知道的知道了" | 修炼禁术、翻阅禁书、触碰禁忌之地 | 普通的知识获取（无禁忌性那是`INFORMATION_EXTRACTION`金手指用法） |
| `TIME_PRESSURE` | 时限压迫，核心是"倒计时" | 限时救人、倒计时解毒、期限内完成任务 | 有充足时间的任务（无时限那不算） |
| `ALLIANCE_FRAGMENT` | 联盟/合作关系的破裂，核心是"合作崩了" | 盟友翻脸、合作破裂、联军解散 | 单纯的背叛（那是`BETRAYAL_REVENGE`） |
| `STATUS_QUO_EXPOSITION` | 日常交代/过渡/清点/世界观展开，无主冲突 | 战利品清点、功法领悟、世界观说明、日常过渡、角色休息 | 有明确冲突的章节（应选其他冲突模式） |

> **`STATUS_QUO_EXPOSITION` 特殊说明**：标记为日常交代章时，系统自动豁免"连续无代价"BLOCKING（因为日常章本来就没有冲突需要解决）。但必须同时将 `resolution_cost` 设为 `NOT_APPLICABLE`，两者配合使用。

## 三、core_trope（核心桥段，45种）

> CD 冷却：**60~80章**（高刺激强套路桥段）。读者在读了20万字后，对上一场拍卖会的微观记忆已经淡化，恰好需要一次经典的爽点释放。但20章内看两次拍卖会 → 吐了。

| `AUCTION_BIDDING` | 拍卖/竞价场景，核心是"加价博弈与捡漏" | 拍卖会截胡、暗标竞争、捡漏无人识货的宝物 |

## 四、golden_finger_mode（金手指用法，18种）

> CD 冷却：**10~15章**。主角不能每次遇到问题都按同一个按钮，必须轮换手段。

| 枚举值 | 定义 | 正例 |
|--------|------|------|
| `WEAKNESS_EXPOSE` | 逆向解析破绽，核心是"找到弱点一击制胜" | 解析眼看穿破绽、分析对手弱点、找到阵法漏洞 |
| `OVERCLOCK_BURST` | 过载透支爆发，核心是"短时间超功率输出" | 燃烧灵力爆发、超频运算、透支体力、狂暴模式 |
| `RULE_BYPASS` | 规则绕过/打破规则，核心是"不按常理出牌" | 无视禁制、绕过规则、卡BUG、打破常规限制 |
| `RESOURCE_SYNTHESIS` | 资源合成/转化，核心是"无中生有或点石成金" | 炼丹合成、点石成金、资源转化、废物利用 |
| `INFORMATION_EXTRACTION` | 信息提取/读取，核心是"知道别人不知道的" | 读心术、鉴定术、回溯记忆、扫描分析 |
| `PROBABILITY_MANIPULATION` | 概率操纵/运气，核心是"改变可能性" | 幸运光环、概率操控、厄运转移、必中必闪 |

## 七、CD 冷却周期配置（权威）

> `nww_trope_guard.py` 读取此配置执行冷却检查。修改此表即修改门禁行为。

| 维度 | 最小冷却窗口（Safe CD） | 冷却恢复期（CD ~ 2×CD） | 记忆遗忘期（≥ 2×CD） | 设计逻辑 |
|------|----------------------|----------------------|---------------------|---------|
| `core_trope` | **70章** | 70~140章 | ≥140章 | 高刺激强套路，20万字后微观记忆淡化，恰好需要经典爽点释放 |
| `conflict_pattern` | **18章** | 18~36章 | ≥36章 | 冲突模式有限，不可避免多次出现，但绝不能连续 |
| `golden_finger_mode` | **12章** | 12~24章 | ≥24章 | 主角不能每次按同一个按钮，必须轮换手段 |
| `resolution_cost` | **30章** | 30~60章 | ≥60章 | 频繁大出血读者会麻木，代价必须有周期性 |
| `character_dynamic` | **20章** | 20~40章 | ≥40章 | 角色交互模式需要变化，避免"每个新角色都是敌对试探" |

### 冷却期行为规则

| 阶段 | 距离 | 行为 |
|------|------|------|
| **绝对红线期** | `distance < Safe CD` | **BLOCKING**：严禁使用，提示剩余冷却章数 |
| **冷却恢复期** | `Safe CD ≤ distance < 2 × Safe CD` | **条件放行**：允许使用，但必须通过变奏检查（见第八节） |
| **记忆遗忘期** | `distance ≥ 2 × Safe CD` | **PASS**：完全解冻，视为常规元素，不做额外检查 |

## 八、变奏检查规则（Variation Gate）

当 `core_trope` 处于冷却恢复期（Safe CD ≤ distance < 2×CD）时，系统允许复用该经典桥段，但**必须满足以下两个条件之一**，否则判定为"换皮复制" → BLOCKING：

### 条件1：结构与博弈层级变奏（Subversion / Twist）

`trope_variant` 字段必须与上次使用时**实质性不同**。变奏方向包括但不限于：

| 变奏类型 | 说明 | 示例（首次 vs 复用） |
|---------|------|-------------------|
| 角色反转 | 主角从被动变主动 | 首次：台下隐忍加价；复用：主角是拍卖师/幕后做局者 |
| 逆向款 | 以为是捡漏，结果是陷阱 | 首次：捡漏无人识货的残片；复用：拍品是陷阱，主角将计就计 |
| 尺度升级 | 博弈筹码量级跃迁 | 首次：新手村市井暗市（灵石）；复用：跨界神魔巨头拍卖（因果/气运） |
| 参与者变化 | 对手层级/身份变化 | 首次：同阶弟子竞争；复用：老怪/巨头参与，主角在夹缝中取利 |
| 结果反转 | 预期结果被颠覆 | 首次：成功拍到；复用：故意不拍，让对手拍下陷阱 |

### 条件2：解法变化（Golden Finger Mode 不同）

`golden_finger_mode` 与上次使用时**不同**。即使桥段结构相似，只要解决问题的手段变了，就不算换皮。

### 变奏检查判定逻辑

```
if core_trope 重复 and 处于冷却恢复期:
    if trope_variant 与上次不同 OR golden_finger_mode 与上次不同:
        → PASS_WITH_ADVISORY("经典桥段合理复用，变奏检查通过")
    else:
        → BLOCKING("虽已过冷却期，但情节走向变奏与上次完全相同，属于换皮，请调整切入角度或更换解法")
```

## 九、repeat_intent 白名单豁免（有意重复）

网文创作中，**有些重复是刻意的、必要的**。`repeat_intent` 字段用于标记这些情况，非 `none` 时硬阻断降级为软告警，但必须通过豁免校验。

| 枚举值 | 定义 | 豁免校验条件 |
|--------|------|------------|
| `none` | 无豁免，正常检查 | （默认值） |
| `foreshadow_payoff` | 伏笔回收 | 必须在 `追踪/伏笔.md` 中存在对应伏笔，且该伏笔的 `planned_resolution_chapter` 与本章匹配或为 null |
| `theme_variation` | 主题变奏 | `bible.json` 的 `creative.core_question` 或 `creative.novelty_pillars` 中存在与本章对应的主题，且 `trope_variant` 描述了变奏方向 |
| `character_growth_parallel` | 角色成长对照 | 对应角色卡（`设定/角色/{名}.md`）中存在成长线记录，且本章是该成长线的对照节点 |
| `genre_convention` | 题材惯例 | `bible.json` 中配置了 `genre_convention_patterns`（数组），且本章 `core_trope` 在该数组中匹配 |

### 豁免行为

- 通过豁免校验 → 硬阻断（BLOCKING）降级为软告警（ADVISORY），提示"本章为有意重复（{类型}），已豁免硬阻断"
- 未通过豁免校验 → 按正常冷却规则执行 BLOCKING
- SimHash 碰撞检测**不受豁免影响**（即使是有意重复，也不应与某章文字级雷同）

## 十、SimHash 语义碰撞参数

> 用于检测"换了枚举名但情节实质相同"的情况。

| 参数 | 值 | 说明 |
|------|-----|------|
| 哈希位数 | **64-bit** | 平衡精度与碰撞率 |
| 特征提取 | **字符 3-gram** | 对 `core_plot_summary` 字段提取，零外部依赖 |
| 雷同判定阈值 | **汉明距离 ≤ 3** | ≤3 判定为语义雷同（64位中差异≤3位） |
| 检测窗口 | **近100章** | 超过100章的相似不检测（记忆遗忘期） |
| 告警级别 | **ADVISORY** | 只告警不阻断，高亮重合章节供人工判断 |

### SimHash 计算说明

1. 输入：`core_plot_summary`（核心情节一句话总结，≤80字）
2. 预处理：去除标点、空白，转为纯中文字符串
3. 提取所有连续3字符子串（3-gram）
4. 每个3-gram哈希到64位整数
5. 对所有哈希值按位统计：每一位出现1的次数 > 出现0的次数 → 该位为1，否则为0
6. 输出64位 SimHash 值

### 汉明距离计算

两个64位 SimHash 值的汉明距离 = 异或后1的个数。≤3 → 语义雷同。

## 十一、组合硬阻断规则（高级）

除了单维度冷却检查外，以下组合规则直接 BLOCKING：

| 规则 | 条件 | 说明 |
|------|------|------|
| **组合碰撞** | 近30章内 `[conflict_pattern + golden_finger_mode]` 完全一致且 `repeat_intent == "none"` | 冲突模式和解法都一样 → 本质是同一章的换皮 |
| **三维雷同** | 近50章内 `[conflict_pattern + core_trope + resolution_cost]` 完全一致 | 冲突、桥段、代价都一样 → 读者会强烈感到"这章我看过" |
| **连续无代价** | 连续3章有冲突但 `resolution_cost=NONE` | **BLOCKING**——无痛解题是爽点贬值核心。精确触发：①当前章=NONE ②当前章conflict_pattern≠STATUS_QUO_EXPOSITION ③前两章都=NONE（NOT_APPLICABLE不参与计数也不中断） |
| **角色模式固化** | 近10章内 `character_dynamic` 同一值出现 ≥4次 | 角色交互模式固化 → advisory提醒轮换 |

## 十三、维护说明

- 枚举库是活的：随着生产实践发现新的冲突模式/桥段，可在此文档中新增枚举值
- 新增枚举值后，存量细纲不受影响（已登记的指纹保持有效），新细纲可使用新枚举
- CD 冷却周期的修改需谨慎：过短 → 雷同拦截不足；过长 → LLM 被逼写生僻情节
- 建议每50章生产后回顾一次：哪些枚举值被过度使用？哪些枚举值从未使用？是否需要新增？
