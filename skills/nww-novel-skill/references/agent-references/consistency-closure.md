# 核验闭环清单（consistency-closure）

一致性审查（`nww-consistency`）输出 S1–S4 分级冲突报告后，用本清单对 S1/S2 冲突做闭环核验。

原则：**S1/S2 不闭环不提交** —— 硬矛盾（S1）与隐性矛盾（S2）必须「修复」或「人工裁决」后才允许进入追踪事务提交；S3/S4 可记待办，不阻断。

---

## 1. 闭环规则

| 级别 | 含义 | 闭环要求 |
|---|---|---|
| S1 (Critical) | 直接矛盾硬伤 | **必须**修复或人工裁决；未闭环不得提交 |
| S2 (Major) | 隐性矛盾破坏叙事逻辑 | **必须**修复或人工裁决；未闭环不得提交 |
| S3 (Minor) | 细节不一致 | 建议修，可记待办 |
| S4 (Advisory) | 伏笔超期/密度/格式 | 记待办，非阻断 |

## 2. 闭环方式

- **修复**：改正文/细纲/设定消除矛盾。修复后重跑一致性检查，确认对应冲突不再出现。
- **人工裁决**：确认为非冲突（叙事留白、设定本意、刻意误导等），须记录裁决理由，由作者或编排者确认后方算闭环。

## 3. 闭环清单模板

```markdown
## 核验闭环清单（第 {N} 章 / 批次）

### 待闭环（S1/S2，必须处理）
- [ ] [S1] {冲突描述} -- 文件:{路径}:{行}
  - 闭环方式：修复 / 人工裁决
  - 状态：未处理 / 已修复 / 已裁决
  - 裁决理由（人工裁决时填写）：{理由}

### 待办（S3/S4，可记待办）
- [ ] [S3] {描述} -- 文件:{路径}:{行}
- [ ] [S4] {描述} -- 文件:{路径}:{行}
```

## 4. 提交闸门

- 存在**未闭环**的 S1/S2 → 禁止进入 `nww_track_commit.py commit`，先回炉修复或完成人工裁决。
- 全部 S1/S2 已「已修复」或「已裁决」→ 允许提交。
- S3/S4 待办记入追踪待办（如有），不阻断提交。

## 5. 机器可读闭环记录（A-3 机械闸输入）

闭环核验完成后，把记录写入 `{BOOK}/追踪/一致性核验/第{N}章.json`（JSON 契约）：

```json
{ "chapter": 5, "closed": true, "open_s1_s2": [], "updated_at": "2026-08-28T12:00:00+08:00" }
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `chapter` | int | 章号 |
| `closed` | bool | 本章 S1/S2 是否全部闭环（修复或人工裁决） |
| `open_s1_s2` | array[string] | 未闭环冲突清单；`[]` = 无 |
| `updated_at` | string | 落盘时间（ISO8601） |

`nww_track_commit.py commit` 在 bible.json `commit_gates.consistency=true` 时机械校验该记录：缺文件 / `closed=false` / `open_s1_s2` 非空 → 拒绝提交；未开启（存量兼容，默认）→ 仅 WARNING 不阻断。人工裁决的裁决理由记入裁决记录（正文外可追溯），附带记入本文件的 `updated_at`。
