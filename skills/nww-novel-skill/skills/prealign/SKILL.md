# nww-prealign — 写前对齐（评分前置 → 产出提高）

**目的**：评分体系不是写后评级，而是**写作前就要用的创作尺**。动笔前先把"这章素材缺不缺钩子/绑定/落差/卡点"检查一遍，缺的补进细纲再进 prompt，让 LLM 首次成稿的基础分就上去（而不是写完再大改）。

**定位**：本条是 `long-write` Phase 1 内嵌"写前评分对齐"检查的**展开说明**（独立执行方式）。规则来源：项目根 `quality/rubric_90score_v3.md`（外部维度第 2 节、内部门禁第 3 节、90 分底线第 6 节）。

**核心原则**：

1. **只查结构层**（缺不缺），执行层（词句密度/节奏力度/AI味）由写后门禁负责。
2. **硬 checklist**：逐项 Pass/Fail，Fail 即回细纲补写，全部通过才进 prompt。不产出长篇报告，不拖慢写作。
3. **缺的补进细纲**，不是靠 LLM 写时即兴——结构层缺失必须在设计阶段解决。

***

## Step 0 · 判定适用对象

- **第 1\~3 章**：执行 **E0 黄金三章链 + E1\~E5 + 门禁** 全量检查（黄金三章定生死，必须前置）。

- **第 4 章及以后**：只执行 **E1\~E5 + 门禁**（E0 已用前三章评过，不再重复）。

所需素材：本章细纲（`大纲/细纲_第{N}章.md`）、`bible.json`、`{BOOK}/追踪/_tracking-state.json`、已有正文章节（前三章衔接用）。E0 黄金三章链额外参考 `references/agent-references/opening-design.md`（开篇设计原则、叙事功能让位原则的唯一定义所在地）。

| 判据           | 检查内容                                | 不通过 → 补进细纲 |
| ------------ | ----------------------------------- | ---------- |

| **G2 章间落差**  | 章与章之间有落差或新钩子，不是平铺三章同强度              | 补一处落差或换强度  |

| **G4 过渡自然**  | 前章末钩子本章开头接住，无"摆好悬念转头忘"              | 修本章开头接续    |

| **G6 金手指基点闭环** | 前三章内金手指完成「发现→验证→使用」闭环；第3章结束前主角至少一次主动选择使用金手指解决冲突（非纯被动承受）；检查素材=细纲节拍中是否有「主角主动使用金手指」节点 | 在第2或第3章补一个金手指主动使用节点（用死回合行动布局/用信息差反制/用收残子获得的能力解决小冲突）；闭环不要求打赢大boss，解决小冲突即算 |
| **G7 开篇爽点密度** | 第1章1000字内出现爽点或期待点（异常/悬念/反差/金手指暗示任一即可）；前三章每章至少一个可感知收益（能力/信息/资源/关系，负收益也算但需标注）；**核心异常/核心卖点须在开篇最早的有效节拍完成一次可感知兑现，不得被多个同功能环境素材延迟（引用叙事功能让位原则，见 opening-design.md）**；检查素材=细纲第1章前2个节拍 + 细纲「本章目标」统率字段（存量书兼容旧「本章收益兑现」字段） | 第1章开篇补一个反常锚点；若开篇同功能环境素材 ≥2 个而主角侧确认/行动未先出现，压缩环境素材并前移主角确认；每章细纲补「本章目标」统率字段或旧「本章收益兑现」字段（与long-write Phase 0硬阻断对齐，2026-09-09起优先统率字段）；连续2章零收益则Fail |
| **G8 卖点显性化** | 第1章结束前读者能回答「这本书的卖点是什么」（金手指/核心冲突/独特设定至少一个被明确展示）；第3章结束前卖点至少完成一次「展示→兑现」；检查素材=细纲第1章是否有卖点展示节点 + 第3章是否有卖点兑现节点 | 第1章补卖点展示（如「死回合只有我能动」在第1章明确展示）；第3章补卖点兑现（用金手指解决一个具体问题，让读者看到卖点的实际价值） |
| **G9 金手指剧情引擎** | 金手指不是「提供力量的死外挂」，而是推动剧情的动态引擎：①本章剧情是否由金手指的特性/限制/代价驱动（而非金手指只是提供力量）；②主角是否与金手指有互动（利用限制/钻漏洞/付出代价/被反噬/系统反制）；③检查素材=bible.creative.goldfinger_interaction（金手指互动方式定义） + 细纲中金手指相关节点 | 若金手指只是「给力量」不参与剧情，回细纲补一个「金手指特性驱动剧情」的节点（如：利用死回合时间差布局→被系统判定精度提高反制；收残子获得走法→走法代价触发新冲突）；bible 缺 goldfinger_interaction 字段则先补 bible（定义金手指与主角的博弈方式，不是「给什么能力」） |

> **判死项（严重违背才触发）**：主角身份/名字/立场不可逆颠倒；三章读完读者无法回答"接下来会发生什么"。软钩子（风格/人设/悬念笼统期待）**算追读理由，不判死**。

### 1C. 章级字数容量（每章都做，V1 冻结判据 2026-09-04）

> 目的：防止细纲"剧情摘要化"导致 Writer 写完剧情就收笔、正文字数长期达不到目标下限。审计对象 = **细纲原文**，不看正文成稿（正文可能已有过程层，但细纲没锁＝下一次 Writer 仍会简写）。
> **核心命题**：一章成稿字数由细纲里每个节点天然具备的**有效过程容量**决定，不由节点数量决定。容量来自**有效回合**，不来自情节点个数。

#### 1C-1 · 逐节点打档（核心单位 = 有效过程链）

每个节点按"过程链"能自然走满几拍来定档，走不满就是低档：

> 动作/提出问题 → 阻力 → 回应 → 新信息 → 再处理 → 对方变化 → 再决策 → 结果

**每轮都必须改变信息状态 / 人物判断 / 关系压力 / 行动方向至少一项**；只是换句话重复＝同档内加水、不算容量。

| 档位     | 有效回合              | 自然有效容量     | 说明              |
| ------ | ----------------- | ---------- | --------------- |
| **小戏** | 1–2 轮             | 250–400    | 发现/交代/收束，信息一次吃完 |
| **中戏** | 2–3 轮             | 400–700    | 有实际交锋或处理过程      |
| **大戏** | 3–5 轮             | 800–1100   | 每轮都有新信息/新反应     |
| **重戏** | 5 轮以上，且至少两个阶段发生变化 | 1200–1600+ | 中途发生一次阶段性改写     |

> 档位是**容量许可**，不是字数要求：标成"重戏"＝细纲允许 Writer 自然写到该量级，不是命令必写多少字。

#### 1C-2 · 整章合格判定（求和 + 三条硬判据）

逐节点打档后，估算 `Σ档位容量`，结合硬判据判定：

| 判据                   | 检查内容                                             | 不通过 → 补进细纲                                                  |
| -------------------- | ------------------------------------------------ | ----------------------------------------------------------- |
| **有效容量求和**           | Σ档位容量 ≥ 本书字数目标带下限（单值按±8%取下限 / 区间取区间下限，见 platform-wordcount.md）→ 视为细纲可承载目标量级               | **< 目标带下限 → 回细纲增加真正的过程戏**（把隐含过程锁进细纲）；≥ 目标带中位 → 停止扩容，防止"为字数加戏" |
| **硬判据 A · 有无重戏**     | 至少 **1 个 800+ 级核心过程节点**（大戏/重戏）                   | 无 → 目标量级章节天然危险，补一个 800+ 过程节点                             |
| **硬判据 B · 有无第二过程支柱** | 至少再 1 个 **700–1000 级**节点                         | 无 → 容易写成"一个场景1200、其余全是300–500"最终只有2500–3000，补第二个过程支柱        |
| **硬判据 C · 大节点是否真有戏** | 800+ 节点 ≥ 3 轮有效变化；1200+ 节点 ≥ 5 轮有效变化且中途至少一次阶段性改写 | 不足 → 回细纲把过程链写足（不是加一句看起来很复杂的结果描述）                            |
| **认知/心理节点封顶**        | "看穿/意识到/决定/想明白"默认只算**中小戏**（400–700），不适用 800+     | 若本章靠认知节点撑 800+，细纲阶段必须把它**外化成戏**：看穿→去验证→对方反应→新证据→再判断→决定      |

> **判定动作（同 V2 语义，FAIL 不改 Writer）**：**FAIL/不足 → 回细纲补过程层**，不新增无关剧情、不灌环境描写、不重复动作、不堆砌内心独白；允许且鼓励的是把既有事件"如何发生"补成可执行过程。

#### 1C-3 · 归档（旧判据 D0–D3 / LC / EC / L3，v2 2026-08-29）

> 以下旧判据不再参与新的容量判定，仅作回滚/追溯依据，不保留为可选路径（回滚点：`skills/nww-novel-skill/skills/prealign/.rollback_capacityV1_20260904/`）。
>
> - 事件簇识别（禁把一个事件拆成多节点凑数）——**语义并入 1C-1**（同一过程链算一个节点，打一档）；
>
> - 展开深度 D0–D3（D0 结果摘要 / D1 单次过程 / D2 有阻碍尝试变化 / D3 有验证·失败调整·选择取舍·关系拉扯致认知变化）——由 1C-1 的四档有效回合判定取代；
>
> - 整章容量 L3 = LC + EC，PASS=LC≥4140 —— 由 1C-2 的 Σ档位≥4000 + 三条硬判据取代。
>
> - 旧判据要点（D3 高展开价值 ≠ LC 已锁定；禁止为凑字数新增剧情/灌水）——语义已并入上方「判定动作」。

### 1D. 结构指纹排重检查（每章都做，零侵入）

> 目的：防止长程剧情结构雷同（连续复读同一解法/桥段/冲突模式），在细纲阶段就拦截高疲劳风险，不要等写完正文才发现"这章我看过"。
> 设计原则：**零侵入**——细纲无 structural_fingerprint 区块时静默放行（SKIPPED），不阻断旧项目/迁移章节；只有主动声明了指纹才介入核验。

| 判据 | 检查方式 | 不通过 → 动作 |
|------|---------|--------------|
| **CD冷却** | 调用 `python3 skills/nww-novel-skill/scripts/nww_trope_guard.py check --chapter <章号> --project <书根>`，检查 conflict_pattern/core_trope/golden_finger_mode/resolution_cost 是否在冷却期内 | 回细纲更换对应维度，或调整到冷却期后使用 |
| **变奏检查** | 冷却恢复期内复用桥段时，trope_variant 或 golden_finger_mode 必须与上次不同 | 回细纲修改 trope_variant（切入角度/角色反转/尺度升级）或更换解法 |
| **连续无代价** | 连续3章有冲突但 resolution_cost=NONE → BLOCKING（日常章 NOT_APPLICABLE 自动豁免） | 回细纲为本章主角安排具体代价，或引入次生危机 |
| **组合碰撞** | 近30章内 [冲突模式+解法] 完全一致 → BLOCKING | 回细纲更换冲突模式或解法 |
| **SimHash语义碰撞** | core_plot_summary 与近100章汉明距离≤3 → ADVISORY | 人工确认是否换皮重复，如是则回细纲调整核心情节 |

**执行方式**：
- 在1A/1B/1C全部Pass后，执行1D检查
- 命令输出 `verdict: PASS` 或 `SKIPPED` → 通过，进入Phase 1
- 命令输出 `verdict: BLOCKING` → 回细纲，按输出的 `suggestions` 修复后重跑
- 命令输出 `ADVISORY` → 不阻断，但需在硬事实锚说明段记录已关注

**零侵入说明**：
- 细纲无 `structural_fingerprint` YAML frontmatter → `verdict: SKIPPED`，静默放行，不影响旧项目
- 日常过渡章设置 `conflict_pattern: STATUS_QUO_EXPOSITION` + `resolution_cost: NOT_APPLICABLE` → 自动豁免代价相关检查
- 有意重复（伏笔回收/主题变奏等）设置 `repeat_intent` 字段 → 硬阻断降级为软告警

***

## Step 2 · 对齐产物

- 全部 Pass → 直接进入 Phase 1 硬事实锚构造（long-write）。

- 存在 Fail → **回细纲补写对应项**（按上表"不通过→补"列），补完重跑本清单确认全 Pass，再进 prompt。

- 不产出独立评分报告；对齐结果（哪些项补过）可并入硬事实锚的说明段，让 LLM 知道自己按什么设计写的。

## 使用示例

> 场景：写第 2 章（前三章内）。细纲第一幕是"沈砚在值房抄文书，发现淮南空白"。
